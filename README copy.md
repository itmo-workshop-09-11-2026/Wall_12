# КосмоМаркет — учебный интернет-магазин

Учебный магазин с интерфейсом на HTML/CSS/JavaScript и backend на Python. Сервер использует только стандартную библиотеку Python: отдельно устанавливать пакеты через `pip` не нужно.

## Возможности

### Интерфейс магазина
- Каталог из шести демонстрационных товаров в трёх категориях.
- Добавление товаров в корзину, изменение количества и удаление.
- Автоматический пересчёт суммы.
- Поиск по названию и описанию, фильтр по категории и сортировка по цене.
- Избранное.
- Сохранение корзины и избранного в `localStorage` после перезагрузки.
- Промокод `SPACE10` на скидку 10%. Повторное применение промокода не увеличивает скидку.
- Адаптация для мобильного экрана и управление с клавиатуры.

### Backend на Python
- `GET /api/products` — каталог товаров.
- `GET /api/products?q=луна` — поиск по названию и описанию.
- `GET /api/products?category=Для%20дома` — фильтр по категории.
- `GET /api/categories` — список категорий.
- `POST /api/orders` — создание заказа с пересчётом суммы на сервере.
- SQLite хранит каталог, остатки, заказы и состав заказов.
- При создании заказа сервер проверяет товары, целые положительные количества и остатки. Цены берутся из базы данных, а не из браузера.
- Заказ уменьшает остатки; транзакция защищает от продажи большего количества товара при одновременных запросах.

Оплата и личные кабинеты не реализованы: это демонстрационный проект.

## Запуск

Нужен Python 3.12 или новее.

**Windows (PowerShell):**

```powershell
py -3 --version
py -3 main.py
```

**macOS / Linux:**

```bash
python3 --version
python3 main.py
```

Откройте в браузере <http://localhost:8000>. Остановка сервера — `Ctrl+C`.

По умолчанию сервер доступен только на этом компьютере. Чтобы выбрать другой порт:

**Windows PowerShell:**

```powershell
$env:PORT = "8001"
py -3 main.py
```

**macOS / Linux:**

```bash
PORT=8001 python3 main.py
```

После запуска откройте <http://localhost:8001>.

При первом запуске создаётся `data/shop.sqlite3` и заполняется демонстрационным каталогом из `site/products.json`. Не удаляйте базу, если хотите сохранить оформленные заказы. Чтобы начать с чистыми данными, остановите сервер и удалите `data/shop.sqlite3` — при следующем запуске база создастся заново.

## Сборка самостоятельного сайта в ZIP

Из корня проекта выполните:

**Windows:**

```powershell
py -3 main.py --pack
```

**macOS / Linux:**

```bash
python3 main.py --pack
```

В корне появится `shop.zip`. Внутри архива `index.html` находится сразу в корне. ZIP содержит только статические файлы из `site/` и работает без Python API — например, через Live Server в VS Code. В этом режиме каталог и корзина работают в браузере, но заказ не записывается в SQLite.

## Проверка

**Windows:**

```powershell
py -3 tests/smoke.py
```

**macOS / Linux:**

```bash
python3 tests/smoke.py
```

Тест запускает сервер с отдельной временной базой, проверяет главную страницу, API, поиск, оформление заказа, обработку некорректного запроса и ZIP. Рабочая база проекта при этом не меняется.

## Структура проекта

```text
cosmomarket/
├── main.py                # Python HTTP-сервер, API и упаковка ZIP
├── README.md              # эта инструкция
├── data/                  # SQLite создаётся автоматически
├── site/
│   ├── index.html         # страница магазина
│   ├── styles.css         # оформление и адаптивная вёрстка
│   ├── app.js             # логика каталога и корзины
│   └── products.json      # начальные товары для backend и ZIP-версии
└── tests/
    └── smoke.py           # проверка основных сценариев
```

## Настройки перед сдачей

В `site/app.js` замените `team07` в `TEAM_KEY` на номер своей команды. Этот префикс используется для ключей `localStorage`, чтобы корзины и избранное разных команд не пересекались.

Каталог можно изменить в `site/products.json`. Для чистой базы удалите `data/shop.sqlite3` перед следующим запуском, чтобы новый каталог загрузился при инициализации.

### Формат API заказа

Запрос:

```http
POST /api/orders
Content-Type: application/json
```

```json
{
  "items": [
    {"productId": "nebula-mug", "quantity": 1},
    {"productId": "mars-stickers", "quantity": 2}
  ],
  "promoCode": "SPACE10"
}
```

Сервер самостоятельно получает цены из SQLite, вычисляет скидку и итог. При нехватке остатка или неизвестном товаре заказ не создаётся.

## Публикация статической версии на GitHub Pages

В проект добавлен workflow `.github/workflows/publish.yml`: он публикует содержимое `site/` при каждом push в ветку `main` и поддерживает ручной запуск.

1. Создайте публичный репозиторий GitHub и загрузите в него файлы проекта.
2. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. Отправьте commit в `main` или запустите workflow **Actions → Publish site → Run workflow**.
4. После успешного выполнения адрес сайта появится в **Settings → Pages** и в результате workflow.

GitHub Pages публикует только статические файлы из `site/`, а Python API и SQLite там не запускаются. Поэтому на GitHub Pages каталог и корзина работают как самостоятельная браузерная демо-версия; для сохранения заказов запускайте Python-сервер локально или размещайте backend отдельно.

## Docker (необязательно)

```bash
docker build -t cosmomarket .
docker run --rm -p 127.0.0.1:8000:8000 -v cosmomarket-data:/app/data cosmomarket
```

Откройте <http://localhost:8000>. Том `cosmomarket-data` сохраняет SQLite-базу между перезапусками контейнера.

При установленном Make доступны команды `make run`, `make pack`, `make test`, `make docker-build` и `make docker-run`.
